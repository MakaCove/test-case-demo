# PRD：UI 自然语言测试任务中心

## 1. 背景与目标

当前平台已具备：
- 项目管理、版本管理；
- 需求资产管理（文本/文档/原型）；
- 用例任务中心（大模型生成功能/接口测试用例）。

为了扩展“自然语言驱动浏览器测试”能力，新增一条独立业务链路：
- 保持原“需求资产”与“用例任务中心”不变；
- 新增“自然语言用例库”作为 UI 自动化测试输入源；
- 新增“UI 自然语言任务中心”实现任务创建、启动、执行、报告闭环；
- 新增“步骤管理”“报告中心”支持执行过程与结果管理。

## 2. 范围定义

### 2.1 本期范围（In Scope）
- 新增菜单与页面：
  - 自然语言用例库
  - UI 自然语言任务中心
  - UI 步骤管理
  - UI 测试报告中心
- 任务生命周期管理：创建、启动、执行、取消、重试、查看详情。
- 自然语言解析为浏览器操作步骤。
- 执行步骤并生成报告（截图、日志、步骤结果）。
- Java 主系统通过 HTTP 调用独立 Runner 服务执行浏览器任务。

### 2.2 非本期范围（Out of Scope）
- 替换或改造现有“需求资产”模型；
- 替换现有“用例任务中心”生成逻辑；
- 多浏览器并行调度与复杂资源编排；
- 复杂可视化回放（可作为后续迭代）。

## 3. 总体方案

### 3.1 业务线拆分
- 原“任务中心”重命名为：`用例任务中心`（原流程不变）。
- 新增：`UI 自然语言任务中心`（独立流程与状态机）。

### 3.2 技术架构
- `backend`（Java）：主业务系统，负责认证、权限、任务/步骤/报告数据管理、前端接口。
- `ui-runner`（Python，新增独立项目）：负责自然语言驱动浏览器执行。
- 通信：`backend -> ui-runner` 通过 HTTP（run/status/cancel）。

### 3.3 项目目录建议
- `backend/`
- `frontend/`
- `ui-runner/`（新增，和 backend 平级）

## 4. 菜单与页面规划

## 4.1 自然语言用例库
用于沉淀和复用自然语言测试描述，归属项目/版本。

功能：
- 新建、编辑、删除、复制；
- 按项目/版本/关键字筛选；
- 详情查看（文本、前置条件、环境参数）；
- 从用例创建 UI 任务。

核心字段：
- `projectId`、`versionId`
- `title`
- `nlText`（自然语言主流程）
- `precondition`（前置条件）
- `targetEnv`（目标环境标识）
- `credentialRef`（凭据引用，禁止明文密码）
- `status`（启用/停用）

## 4.2 UI 自然语言任务中心
用于将自然语言用例实例化为执行任务。

功能：
- 新建任务（选择项目/版本/自然语言用例 + 运行参数）；
- 启动、取消、重试；
- 列表展示状态与关键信息；
- 进入步骤管理、报告详情。

建议状态机：
- `PENDING`：待启动
- `QUEUED`：排队中
- `PLANNING`：解析自然语言中
- `READY`：步骤已生成，待执行
- `RUNNING`：执行中
- `COMPLETED`：已完成
- `FAILED`：失败
- `CANCELLED`：已取消

## 4.3 UI 步骤管理
用于管理“解析产物（步骤）”与“执行结果（每步状态）”。

功能：
- 列表查看任务下步骤摘要；
- 步骤详情（动作、定位、输入、断言、耗时、截图）；
- 执行按钮（整套执行，后续可支持从某步重跑）。

步骤建议字段：
- `stepNo`
- `actionType`（click/type/select/wait/assert 等）
- `target`（定位信息）
- `inputValue`
- `expected`
- `status`
- `durationMs`
- `errorMessage`
- `screenshotPath`

## 4.4 UI 测试报告中心
用于汇总执行结果，提供可追溯报告。

功能：
- 报告列表（按项目/版本/状态/时间筛选）；
- 报告详情（总体结果 + 每步执行明细 + 附件）；
- 从任务中心/步骤页跳转报告详情。

报告建议内容：
- 任务信息、环境信息、执行时间；
- 总步数/成功步数/失败步数；
- 失败原因摘要；
- 附件（截图、日志、trace、视频可选）。

## 5. 后端接口规划（建议）

统一前缀：`/api/v1/ui-nl-*`

自然语言用例库：
- `POST /api/v1/ui-nl-cases`
- `GET /api/v1/ui-nl-cases`
- `GET /api/v1/ui-nl-cases/{id}`
- `PUT /api/v1/ui-nl-cases/{id}`
- `DELETE /api/v1/ui-nl-cases/{id}`

UI 任务中心：
- `POST /api/v1/ui-nl-tasks`
- `GET /api/v1/ui-nl-tasks`
- `GET /api/v1/ui-nl-tasks/{id}`
- `POST /api/v1/ui-nl-tasks/{id}/start`
- `POST /api/v1/ui-nl-tasks/{id}/cancel`
- `POST /api/v1/ui-nl-tasks/{id}/retry`

步骤管理：
- `GET /api/v1/ui-nl-tasks/{id}/steps`
- `GET /api/v1/ui-nl-steps/{stepId}`
- `POST /api/v1/ui-nl-tasks/{id}/execute`

报告中心：
- `GET /api/v1/ui-nl-reports`
- `GET /api/v1/ui-nl-reports/{id}`

## 6. Runner 对接协议（建议）

Runner 服务 API：
- `POST /run`
- `GET /runs/{runId}`
- `POST /runs/{runId}/cancel`

执行建议：
- 后端提交任务后保存 `runnerRunId`；
- 后端定时轮询 Runner 状态；
- 状态变化时回写任务、步骤、报告；
- 超时与失败统一映射为平台错误码与状态。

## 7. 数据与安全要求

- 凭据必须使用引用方式（`credentialRef`），禁止明文入库；
- 日志输出需脱敏（账号、token、cookie）；
- 任务执行需设置超时；
- 限制并发（首期建议 1~2）；
- 所有执行结果可追溯（日志 + 截图 + 状态时间线）。

## 8. 非功能需求

- 可用性：失败可重试、可取消；
- 可观测性：任务、步骤、报告均可查看；
- 可维护性：与现有“需求资产/用例任务中心”解耦；
- 可扩展性：后续可支持更多动作类型、断言类型、回放能力。

## 9. 分期实施建议

Phase 1（最小可用闭环）：
- 自然语言用例库 + UI 任务中心 + Runner 对接（创建/启动/状态）；
- 任务执行结果落报告摘要。

Phase 2（过程可视化）：
- 步骤管理列表/详情；
- 每步截图、错误信息、耗时展示。

Phase 3（增强能力）：
- 报告中心完善（筛选、导出、统计）；
- 支持从某步重跑、模板化步骤、更多断言能力。

## 10. 验收标准（DoD）

- 能在项目/版本下新增自然语言用例并持久化；
- 能基于自然语言用例创建 UI 任务并启动；
- 任务状态完整流转并可查询；
- 可查看步骤列表与步骤详情；
- 执行完成后可在报告中心查看报告，并可从任务页跳转；
- 不影响现有“需求资产”和“用例任务中心”流程。
